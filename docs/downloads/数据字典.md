# 数据字典与口径

粒度：一行一个hero_id × league_id；赛事ID为届次，不等同游戏S赛季。历史与当前英雄名都保留，身份以ID关联。

| 字段 | 单位/含义 | 处理 |
|---|---|---|
| hero_id / league_id | 官方英雄ID / 官方赛事ID | 复合唯一键 |
| event_start / event_end | 官方赛事窗口 | 不当作每场日期；进行中截止未完成 |
| battles / wins / losses | 统计块的战斗/胜/负场次 | wins+losses=battles且胜率一致才允许贝叶斯推断 |
| picks / bans | BP统计块计数 | 不用picks替换battles；与战斗场次不同另记标记 |
| winRate | 官方原始0-1胜率 | 表示已观察表现 |
| pickRate / banRate | 官方BP块0-1比例 | 分母由源口径决定；整块占位零转null |
| posteriorRate | (wins+10)/(battles+20) | Beta(10,10)后验均值 |
| lowerRate / upperRate | 95%可信区间 | Beta后验分位数；简化二项模型，非因果区间 |
| probAbove50 | 后验Pr(p>0.5) | 条件于先验和模型假设 |
| winPercentile / pickPercentile / banPercentile | 同赛事可建模英雄中rank(pct=True) | 平均并列名次除以有效英雄数 |
| score | 100×(0.60winPercentile+0.25pickPercentile+0.15banPercentile) | 同赛事相对表现；不是跨赛事绝对量 |
| top10WeightShare | 1000组权重情景进入前十占比 | 不作胜率概率，数据固定 |
| rankP10 / rankP90 | 权重情景排名分位数 | 不作统计置信区间 |
| pareto | 三维无支配标记 | 同届下有无其他英雄三维不差且至少一维更好 |
| roles / role | 当前官方推荐分路集合 / 首个标签 | 不是历史每局真实分路；多分路筛选可重叠 |
| kda / gold | 官方平均KDA / 平均经济 | 保留用于画像；不直接把它们解释为强度 |
| bp_games_inferred | picks/pickRate中位数四舍五入 | 仅诊断，不作为精确独立比赛总数 |
| source_class | official_public_aggregate / user_manual_unverified / authorized_camp_aggregate | 来源分类不混用 |
| retrieved_at | UTC采集完成时间 | 不等于数据观察截止；原始meta保存准确时间 |

质量标记：bp_not_recorded_all_zero_block=全赛事BP整块占位零；outcome_counts_inconsistent=胜负不合计或计数异常；win_rate_count_mismatch=公布胜率与胜场/战斗场次不符；bp_pick_differs_from_battle_count=两个统计块口径不同；invalid_*或bp_sum_over_one=范围异常。

2019年385条BP占位记录保留胜率数据，BP三维指数为null。20条计数不一致记录保留原始指标，但后验为空。没有BP数据不等于出场率0%。

回测MAE单位为百分点。weightedMaePP单届内以目标battles加权；报告表格取测试届次等权平均。Brier单届以胜负次数计算，不能将同局多英雄当作独立样本用于显著性检验。

## 第三方日常公开样本（独立表）

- `daily_current`：一行一个来源英雄/玩法ID×分段，538条；日期来自提供者公告的daily标签。`winRate/pickRate/banRate/bpRate`均为0–1比例。原始ban数组第二项对应展示禁用率。
- `daily_history`：一行一个英雄×分段×日期，4英雄39,344条，三指标完整33,805条。缺失不填0；完全相同重复日去重，冲突重复直接报错。来源英雄ID不强行等同官方英雄表（含玩法与形态条目）。
- `daily_coverage`：每英雄×分段的完整性、首次/最近完整日期及源日期断档审计。
- `daily_reconciliation`：当前与历史末日16组对比；12组存在数值或缺失差异。delta字段单位是百分点，未确认差异原因，不混合两端数据。
- `daily_summary`：采集覆盖摘要；`sample_sizes_available=false`、`officially_reconciled=false`、`season_mapping_available=false`。
- `daily_source_manifest`：原始URL、采集时间、SHA-256、请求方法和来源分类。所有数据的`source_class=third_party_public_aggregate`，`sample_size=null`，不套用Beta/二项置信推断。

完整解释与复现见《替代数据源核验.md》。这些表不写入KPL模型和营地授权表，也不通过日均指标计算不存在分母的赛季整体胜率。


## 综合榜替代规则

以下为V1旧发布档案定义，不对应新model_rankings页面：`strength_rankings.overallBasis`取balanced（双场景各50%）、daily_only（赛事无有效评分，100%日常替代）或unavailable（未评分）。`scoreReason`是页面显示的具体依据。`arenaScore`缺失保持null，即使采用日常替代也不伪造赛事分；`dailyScore`缺失时不评分。`strength_contexts.combined_count`和`daily_only_count`给出各上下文两类已评分英雄的数量。旧发布Top10、分路Top5和总榜曾共用此规则；新页面采用下文V2模型查询。

## 强度解读派生表（2026-10-11）

| 表 | 粒度 | 字段与规则 |
|---|---|---|
| strength_analysis_points | 已评分英雄×榜单上下文 | context_id、dimension、hero_id、hero/name、rank、roles；score及winPoints/pickPoints/banPoints（单位为分，三项精确合计score）；winRate/pickRate/banRate为0–1；arenaScore/dailyScore；sceneGap仅综合双场景为D−T；banPressure为描述性阈值色组；battles只在赛事场景提供 |
| strength_analysis_drivers | 已评分英雄×上下文×评分驱动 | 每个英雄三行，driver为胜率贡献/出场贡献/ban贡献，contribution为对应分值；score与basis沿用原榜单，瀑布图的起点0和终点score作为独立受审数据输入，不计为额外观测 |
| strength_analysis_history | 当前官方英雄×已结束常规KPL赛事 | 16届×133位=2,128行；eventStart是真实赛事开始日期，score/rank/battles/posteriorRate/basis沿用赛事榜单；无有效评分时保留null |

以上表均输出JSON、CSV及SQLite，由离线prepare_daily_sources或分析流程重建。name是图表身份展示别名，与hero相同；不改变英雄主键或评分总体。

## V2新增派生表

- model_rankings：键model/context_id/scope/hero_id；同英雄可参与多推荐分路。wRaw是评分用W（赛事为后验），winRate是原始；所有率/P/Normalized为0–1；E/B/score/contribution为0–100分；Z无单位，σ总体标准差，BP调整仅用于Z。null是真缺失或不可评分。
- model_contexts：各模型/场景/范围有效比较池、默认权重、事件日期和来源。
- daily_observations：仅D有效者的诊断档案；不再单独展示。model_rankings同榜route=daily_fallback，实际0/100场景权重，scoreBasis与arenaMissingReason解释来源；双有效route=paired、实际30/70。
- coverage_audit / coverage_summary / bp_contract_audit：逐目录英雄覆盖、互斥主要原因、原值和BP口径诊断。battles仅赛事；日常未知不填0。
- model_comparison：同交集模型与同分路权重排名相关、Top10保留；model_sensitivity：预设E/B和T/D权重情景；model_representatives：三英雄9场景对照。
- lane_coverage：最新赛事/四档D/四档C独立分路池；current roles不代表actual positions。
- model_temporal_pairs / model_temporal_validation / model_temporal_exclusions / model_validation_summary：时间转移目标、窗口排除与描述关联结果，未训练未来数据。
- model_release：精确输入/核心代码指纹门槛；validated_descriptive_experiment不表示预测优越。

完整reviewed_snapshot.json包含全部查询。网页构建每个surface只带实际使用的查询，每个保留查询的行和字段完全相同，sourceSnapshotSha256指向完整档案。浏览器下载CSV与主数据由同一流水线生成；并非手工修改JSON。离线构建包含页面所用全部数据，完整历史可从下载CSV复查。
